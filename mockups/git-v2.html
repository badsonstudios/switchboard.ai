  • No grouping. Staged, unstaged, untracked and (if they ever happen) conflicted files are one undifferentiated list. The only hint is a word chip.
  • Path truncates the wrong end. The identifying part of a path is its tail; the rail cuts the tail off.

1Changes, regrouped — the source-control sidebar

The sidebar's job is triage, not reading. Resource groups come straight from VS Code's scmResourceGroup model (merge / index / workingTree / untracked), each collapsible, each with its own count and its own group actions. Rows are name-first, directory-second, so the thing you're looking for never truncates. Status is one coloured letter. Per-file +/− on the right, swapped for hover actions when you reach for them.

  • Stolen: resource groups. VS Code's git extension registers 19 group-level actions keyed on scmResourceGroup and 46 row-level ones. The grouping is the fix for "everything smashed together" — nothing else in this screen matters as much.
  • Stolen: name + description rows. VS Code renders the basename as the label and the directory as a dimmed description. Reverses which end truncates.
  • Stolen: hover-only inline actions (inline@1 open, inline@2 stage/discard). The row stays readable until you aim at it; stats and actions share the same slot.
  • New: status letters, not words. M A D R U ? — git's own vocabulary, coloured, 11px, tooltip carries the word. A rename shows new ← old.

3The diff is a dock panel, not a tab body

This is the structural change. Today the Monaco diff lives inside the Changes tab, and card tabs are mutually exclusive — so you cannot watch the session and read its diff at once. Instead a diff opens as its own dockview panel in the document area, exactly as a doc- viewer already does: a diff- panel family with the same open/focus registry, the same tab strip, the same drag targets. Pop-out then comes for free, because dockview popout groups are already wired (popout-bounds.ts, app:popoutGeometryChanged).

4Popped out — its own OS window, resizable, closable

The explicit ask. A real BrowserWindow via dockview's popout group: move it to the other monitor, resize it, leave it open across tab switches, close it with its own ✕ and the panel returns to the dock. Geometry is saved by the existing popout-bounds plumbing, so it reopens where you left it.

9The git commands behind it — and why no new library

Everything above is the system git binary through the existing hardened GitService spawn wrapper (budgets, kill-tree, the repo-config-guard). No simple-git, no isomorphic-git, no nodegit. We steal VS Code's command shapes, not a dependency. Formats below are read off VS Code's extensions/git/dist/main.js.

SurfaceCommandNote
status (exists) status -z -u --porcelain=v1Already parsed into GitFileStatus.
per-file +/− new diff --numstat · diff --cached --numstat Two calls, merged per path. Binary files report -/-.
log / graph missing entirely log --format=%H%n%aN%n%aE%n%at%n%ct%n%P%n%D%n%B -z --shortstat --diff-merges=first-parent The one contract worth copying verbatim. -z NUL-frames records so a commit body with newlines in it cannot split a record — and this repo's commit bodies are full of them. --shortstat trails after the NUL.
graph for specific refs log … --topo-order --decorate=full --stdin ← refnames on stdin How VS Code draws more than one branch in one graph.
one commitshow -s --decorate=full --shortstat --format=<above> -z <sha> -- Same parser, one record.
a commit's filesdiff --numstat --name-status -z <parent> <sha> Root commit: parent is the empty tree, hash-object -t tree /dev/null → 4b825dc….
ahead / behindrev-list --left-right --count @{u}...HEAD GitStatus already has the fields; nothing populates or reads them.
file historylog --follow --format=<above> -z -- <path> Powers ⏱ and the Timeline equivalent.
stage / unstage fileadd -- <path> · reset -q HEAD -- <path>—
stage hunk / selectionapply --cached --unidiff-zero - ← synthesised patch on stdin VS Code synthesises a one-hunk patch and feeds it on stdin. Never touches the worktree.
discardcheckout -q -- <path> · clean -f -- <path> Destructive — needs a confirm, and the confirm needs to name the file count.
commitcommit --file=- ← message on stdin On stdin, never -m: a multi-line body with quotes in it is a quoting bug waiting to happen on Windows.
worktreesworktree list --porcelainFeeds the ⑂ chips and the worktree filter.
  • Why not a library. nodegit is native bindings with known Electron memory leaks; isomorphic-git buys browser portability we will never use and is slower on large repos; simple-git is a thin wrapper over the same binary we already spawn, and would replace a wrapper that already does budget-kill, tree-kill and config-guard with one that does none of those.
  • Why not a diff renderer. diff2html / react-diff-view / @git-diff-view all render a unified diff to HTML. We have Monaco — the component VS Code itself uses — already in the entry chunk, with word-level diff, synchronised scroll, a real find, and the folding we need for the multi-file view. The only thing Monaco has nothing for is the graph lanes, which is ~200 lines of SVG over parentIds and does not justify a dependency either.
  • Every write operation is a new capability in shared/ipc/capabilities.ts: git.write for staging/commit, kept distinct from today's git.read, so a session cannot mutate a repo through a channel that only ever read one.
